# 广义五子棋：设计与实验报告草稿

## 1. 总体设计

规则引擎 `Game` 保存 N×N 二维棋盘、当前执棋方、落子历史和结果。空格/黑棋/白棋编码为 0/1/2。
每次落子验证类型、边界和空位，从落点沿横、竖及两条斜线的正反方向计数，达到 K 即获胜，包含长连。
未出现获胜且棋盘填满时判和。逻辑只依赖 N、K，不固定棋盘大小或五连。

CLI 与 Tk GUI 共用引擎。人人模式双方输入；人机模式仅为电脑执棋方创建 AI；机机模式为双方创建 AI。
每局重新构造 AI 实例，可加载任意符合协议的独立 Python 文件。GUI 使用后台线程计算，主线程通过队列接收结果并绘图。
重新开始以局次编号丢弃旧线程结果，避免旧棋局落子进入新棋局。

## 2. AI 算法

### 2.1 Minimax 与 Alpha-Beta

采用零和博弈 Minimax 的 Negamax 写法：当前方分值等于下一方分值取负。
搜索终局使用绝对值很大的胜负分值，越早获胜分值越高；深度为零时启发式估值。

```text
search(board, player, depth, alpha, beta):
    检查时间；若无空格，返回 0
    若 depth == 0，返回 evaluate(board, player)
    value = -infinity
    对每个候选 move：
        落子
        若该步获胜：score = MATE - ply
        否则：score = -search(board, opponent, depth-1, -beta, -alpha)
        撤销落子（即使因超时异常退出，也保证撤销）
        value = max(value, score)
        alpha = max(alpha, score)
        若 alpha >= beta：剪枝
    返回 value
```

### 2.2 评估函数

枚举四个方向的全部长度为 K 的窗口。若窗口只含某方棋子及空格，则按棋子数量 i 赋予
`w(i) = 10^(6*i/K)`，`w(0)=0`；同时含双方棋子的窗口计 0。当前方窗口分数减去对方窗口分数即为估值。
指数随 i/K 变化，使连珠目标改变时权重仍可自适应且保持有限范围。
这能奖励接近连珠的局部结构，但会重复计入重叠窗口，也没有完整表达双威胁或长强制变化。

### 2.3 候选、排序与战术检查

根节点先遍历所有空位检查直接获胜点与对手的直接获胜点；能赢则立即下，只有一个必须防守点则直接封堵。
常规搜索从已有棋子周围切比雪夫距离 2 内的空格生成候选。按假设落子后连续棋子数、开放端点数、对手威胁排序。
浅层最多保留 18 个候选，深层最多 12 个。直接获胜或防守候选优先保留，不受普通候选数量截断影响。
空盘选中心。候选筛选属于选择性搜索，会遗漏部分远处或排序靠后的战略着法，不能声称找到全局最优解。

### 2.4 时间管理与协议

从一层开始迭代加深，每完成一整层才替换最终答案。提前保留合法备用落子，超时中断时返回最后完整层结果。
使用 `time.perf_counter()`，留出约 10% 且通常不超过 0.15 秒的预算余量，极短预算最低预留 0.005 秒。
候选生成和估值过程中也检查时间。只搜索棋盘副本，不修改调用者数据；没有网络调用或固定应答表。
由于操作系统调度和 Python 运行开销，极端小于毫秒级的时限无法保证；默认 5 秒时限应通过裁判实测。

## 3. 实验方法

使用 `experiments.py` 自动生成原始 CSV 与统计。默认比较 (5,3)、(9,4) 两组参数，每组对随机 AI 40 局，先后手各 20 局；
相同 AI 自我对战 8 局，另与最多一层搜索的 AI 对战 8 局。对局交替执黑执白。
统计胜负、按所有落子加权的平均每步时间、平均对局长度和异常。随机种子固定，但墙钟截止会引入一定运行差异。
结果只代表指定机器、配置、时限和对手。短时限实验不能替代默认 5 秒及更大棋盘测试。

### 结果分析

本次实际运行命令为 `python assignment1/experiments.py --time 0.05`，共 112 局。
在 (5,3) 和 (9,4) 上，对随机 AI 的胜率分别为 97.5% 和 100%，说明短时限下也能显著优于随机落子。
(5,3) 中后手有一局失利，表明实现并非无敌，短目标连珠下对手也可能形成无法兼顾的威胁。
自我对战两组都是先手获胜，A 因交换先后手最终各胜 4 局；这仅是该实现和短时限下的观察，不是游戏理论上的证明。
在 (9,4) 的小样本深度对比中，迭代加深 AI 8 胜 0 负；在 (5,3) 中双方交替先手后胜负相同，未观察到优势。
全部 112 局未记录协议失败。平均思考时间低于上限，因为开局、直接获胜和唯一防守位置会提前返回。

## 4. 局限与改进

- 窗口估值易重复计算，缺乏精确的威胁空间搜索；可增加双威胁识别，并用消融实验检验作用。
- 候选截断降低分支数，也可能舍弃好棋；可比较不同候选数和搜索深度的时间/棋力权衡。
- 每个叶节点重新扫描所有窗口，较大棋盘时开销较高；可做局部增量估值和置换表。
- 自我对战和深度对比样本较小，不能将少量胜负解释为显著优势。
- 当前未实现 MCTS，进阶部分为迭代加深和着法排序。


在原有 Minimax 框架上增加显式威胁分析：对每个未被对方阻断的 K 格窗口，按空格数分类。
一个空格表示直接获胜点；两个空格表示落在其中一格后，另一格成为获胜点。
同一候选落子能产生两个不同获胜点，才视为双获胜点威胁，涵盖活四、双四，避免重叠窗口重复计数。
三个空格的窗口用于识别下一步形成活四的延伸，并按方向汇总活三/跳三，进而提高双三、四三的优先级。
双三和四三只是启发式强威胁，不被当作数学意义上的必胜；对手的冲四反击仍需搜索。

根节点在没有直接胜负威胁时，优先走自身双获胜点；若对手有此类下一步威胁，则检查候选防守后是否消除了全部威胁，
同时允许己方先冲四争取主动权。深度截止处遇到直接获胜点或对手双获胜点威胁时，最多延伸 4 层，减轻搜索视野问题。
缓存有容量限制，所有扫描仍检查原有时间预算；本次 11 项测试通过，新增战术案例覆盖两种执棋颜色和不同 K。

上面的 112 局实验和原课程裁判结果均来自增强前版本，保留作历史记录，不代表当前版本棋力。
